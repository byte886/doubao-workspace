# Doubao 工作区总览（README）

这是豆包（AI 助手）在本机的**总工作区与长效记忆根目录**。目标：任何一次新对话、任何一个新接手的 AI，看这一页就能知道"东西在哪、按什么规矩干活、怎么恢复对用户的了解"。

> 本文件只做**导航**。具体规则看 AGENTS.md，具体事实看 PROFILE.md，这里不复制其内容（单一数据源，避免漂移）。
> 最后更新：2026-09-07

---

## 一、目录地图

| 路径 | 是什么 | 谁维护 |
|------|--------|--------|
| `AGENTS.md` | **全局工作规则**（怎么干活）：记忆机制、归档、搜索、诚实性等；`~/Doubao/` 树下开对话时自动注入 | 用户与 AI 共建 |
| `PROFILE.md` | **个人白盒事实层**（跨会话记忆）：身份/偏好、项目索引、外部资源指针，四分区 | AI 任务收尾增量写 |
| `skills/` | **自建技能唯一根目录**（"怎么做"的可复用流程），共 8 个，见下方清单 | 用户与 AI 共建 |
| `chats/` | **对话/项目工作区**，按日期分目录（如 `chats/2026-08-26/.../gaodun-course-knowledge-base`） | 每次任务产生 |
| 飞书知识库 | **任务成品归档处**（不在本地），7 个空间的归位路由表见 `PROFILE.md` 4.1 | 按归档规则 |

## 二、四层是怎么协作的

```
规则层 AGENTS.md   → 怎么干活（每次自动加载，改后需重启豆包生效）
事实层 PROFILE.md  → 是谁/要什么/资源在哪（每次新对话主动读）
能力层 skills/     → 可复用的操作流程（任务匹配时按需加载）
成品层 飞书知识库   → 做完的文档/方案/代码成品（任务收尾询问后归档）
```

记忆写入闭环：**准入判断 → 反向出口（流程类去 skills，不进记忆）→ 四分类落 PROFILE → 带日期、写入前告知**。详见 `AGENTS.md` 第一章。

## 三、AI 冷启动顺序（新对话必读）

1. `AGENTS.md` 已自动注入，按其规则执行；
2. 主动读 `PROFILE.md`，恢复用户画像、项目索引与资源位置；
3. 若选了某个项目文件夹，再读该项目自己的 `AGENTS.md` 与台账——项目内规则优先于全局。

## 四、自建技能清单（`skills/`，唯一根目录）

| 技能 | 用途 |
|------|------|
| `mac-system-toolkit` | Mac 七合一：桌面控制、浏览器自动化、窗口管理、电源、硬件健康、VPN 代理、文件搜索 |
| `web-research-toolkit` | 网络调研、网页批量采集转结构化、事实核查与信源溯源 |
| `multiplatform-media-fetch` | YouTube / B站 / 抖音音视频下载与离线语音转写 |
| `work-doc-extract` | PDF/扫描件/Office/图片的内容提取与 OCR，统一输出 Markdown |
| `image-text-redact` | 截图、长图、文本中敏感信息脱敏打码 |
| `photo-organize` | 家庭照片批量整理：人脸预筛、联系表、分类、查重、完整性校验 |
| `face-detect` | 基于 macOS Vision 的本地批量人脸检测（文件名→人脸数） |
| `captcha-reader` | 浏览器自动化中图形验证码的图像增强与识别辅助 |

> 新建技能一律放 `skills/`；官方技能在应用内部目录，不放个人产物。技能只存"怎么做"，与记忆分工见 `AGENTS.md` 1.2。

## 五、维护约定（速查）

- 改了 `AGENTS.md`：**完全退出并重启豆包**才在新对话生效（启动时缓存）；改 `PROFILE.md` 无需重启。
- `PROFILE.md` 控制在 200 行内，超线的拆分方案见 `AGENTS.md` 1.4，拆分前先跟用户说明。
- 归档成品按 `PROFILE.md` 4.1 路由表"按主题归位"，拿不准先问，不默认塞「AI」空间。
- 不回溯整理历史，只沉淀今后任务中产生的有效事实；过时记忆标退役不硬删。
- 口令："**更新记忆**"=立即固化本轮该记的内容；"**读记忆**"=重读 PROFILE 并汇报要点。
